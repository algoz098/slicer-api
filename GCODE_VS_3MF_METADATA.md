# GCode vs .gcode.3mf: Como Metadados São Armazenados

## 🎯 Pergunta

**"A K2 Pro recebe apenas um arquivo GCode, correto? Diferente da Bambu que usa um gcode.3mf. O 3mf permite informar internamente quais as cores e tipo de filamento que devem ser usados na execução do gcode. Mas se o K2 Pro usa apenas GCode, como isso é feito?"**

---

## ✅ Resposta Resumida

**Sim, K2 Plus recebe apenas GCode puro (.gcode).**

**Como os metadados são armazenados?**
- **Bambu Lab**: Usa `.gcode.3mf` (arquivo ZIP com GCode + metadados XML)
- **Klipper/K2 Plus**: Usa **comentários no cabeçalho do GCode** (linhas começando com `;`)

**Arquivo**: `src/libslic3r/GCode.cpp` (Linhas 2640-2680)

```cpp
void GCode::_do_export(Print& print, GCodeOutputStream &file, ThumbnailsGeneratorCallback thumbnail_cb)
{
    // 1. HEADER_BLOCK_START
    file.write_format("; HEADER_BLOCK_START\n");
    file.write_format("; generated by %s on %s\n", 
                     Slic3r::header_slic3r_generated2().c_str(),
                     Slic3r::Utils::local_timestamp().c_str());
    
    // 2. Informações de filamento
    std::string filament_density_list = "; filament_density: ";
    (filament_density_list += m_config.filament_density.serialize()) += '\n';
    file.writeln(filament_density_list);
    
    std::string filament_diameter_list = "; filament_diameter: ";
    (filament_diameter_list += m_config.filament_diameter.serialize()) += '\n';
    file.writeln(filament_diameter_list);
    
    // 3. UUID único
    std::string creality_uuid_str = "; creality_uuid: ";
    boost::uuids::uuid uuid = boost::uuids::random_generator()();
    m_gcode_uuid = to_string(uuid);
    (creality_uuid_str += m_gcode_uuid) += '\n';
    file.writeln(creality_uuid_str);
    
    file.write_format("; HEADER_BLOCK_END\n\n");
    
    // 4. CONFIG_BLOCK_START (configuração completa)
    file.write("; CONFIG_BLOCK_START\n");
    std::string full_config;
    append_full_config(print, full_config);
    if (!full_config.empty())
        file.write(full_config);
    file.write("; CONFIG_BLOCK_END\n\n");
}
```

### Função append_full_config

**Arquivo**: `src/libslic3r/GCode.cpp` (Linhas 5498-5550)

```cpp
void GCode::append_full_config(const Print &print, std::string &str)
{
    const DynamicPrintConfig &cfg = print.full_print_config();
    
    // Lista de chaves proibidas (não incluir no GCode)
    static const std::set<std::string_view> banned_keys({
        "compatible_printers"sv,
        "compatible_prints"sv,
        "print_host"sv,
        "printhost_apikey"sv,  // ← Segurança!
        "printhost_password"sv,
        // ...
    });
    
    std::ostringstream ss;
    
    // Serializar TODAS as configurações (exceto banned_keys)
    for (const std::string& key : cfg.keys()) {
        if (!is_banned(key) && !cfg.option(key)->is_nil()) {
            // Formato: ; key = value
            ss << "; " << key << " = " << cfg.opt_serialize(key) << "\n";
        }
    }
    
    str += ss.str();
}
```

**Resultado**: Todas as configurações do slicer são escritas como comentários!

    metadata = {
        'size': os.path.getsize(file_path),
        'modified': os.path.getmtime(file_path),
        'slicer': None,
        'filament_total': 0,
        'estimated_time': 0,
        'thumbnails': [],
        'first_layer_height': None,
        'layer_height': None,
        'object_height': None,
        'filament_type': None,
        'filament_name': None,
        'nozzle_diameter': None,
    }
    
    with open(file_path, 'r') as f:
        for line in f:
            if not line.startswith(';'):
                break  # Fim do cabeçalho

    return metadata

## 📊 Comparação Final

| Aspecto | .gcode.3mf (Bambu) | .gcode (Klipper) |
|---------|-------------------|------------------|
| **Formato** | ZIP (binário) | Texto puro |
| **Metadados** | XML estruturado | Comentários GCode |
| **Localização** | Arquivo separado | Cabeçalho do GCode |
| **Thumbnails** | PNG embutido | Não suportado* |
| **Editável** | Não (precisa descompactar) | Sim (editor de texto) |
| **Tamanho** | Maior (~10-20% overhead) | Menor |
| **Compatibilidade** | Apenas Bambu | Universal (qualquer firmware) |
| **Parsing** | Requer XML parser | Simples (regex) |
| **Extensibilidade** | Limitada ao schema XML | Ilimitada (qualquer comentário) |

\* Moonraker suporta thumbnails em comentários especiais (base64)

## 🔑 Principais Diferenças

### 1. **Filosofia**

- **Bambu**: Formato rico, estruturado, proprietário
- **Klipper**: Simples, texto puro, universal

---

### 2. **Acesso aos Metadados**

- **Bambu**: Precisa descompactar ZIP e parsear XML
- **Klipper**: Lê diretamente do arquivo (primeiras linhas)

---

### 3. **Modificação**

- **Bambu**: Difícil (requer recompactar ZIP)
- **Klipper**: Fácil (editar texto)

---

### 4. **Compatibilidade**

- **Bambu**: Apenas impressoras Bambu Lab
- **Klipper**: Qualquer firmware que leia GCode

## 💡 Conclusão

### Como K2 Plus Sabe Quais Filamentos Usar?

**Resposta**: Através de **comentários no cabeçalho do GCode**.

**Processo**:
1. CrealityPrint gera GCode com metadados completos no cabeçalho
2. Moonraker lê e parseia os comentários ao receber o arquivo
3. Interface web (Mainsail/Fluidd) exibe as informações
4. Klipper executa o GCode normalmente (ignora comentários)
5. Comandos `T0`, `T1`, `T2` no GCode fazem a troca de ferramenta

**Vantagens sobre .gcode.3mf**:
- ✅ Formato universal (funciona em qualquer sistema)
- ✅ Texto puro (fácil de debugar)
- ✅ Editável manualmente
- ✅ Menor overhead

**Desvantagens**:
- ❌ Sem thumbnails nativos (precisa base64 em comentários)
- ❌ Menos estruturado que XML
- ❌ Parsing mais "frágil" (depende de formato exato)
